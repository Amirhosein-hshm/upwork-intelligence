# ۰۷ — راهنمای یادگیری Telegram Serverless و ابزارهای پروژه

> **تغییر نسبت به نسخه‌ی قبل:** بخش n8n حذف شد. مسیر فعلی Telegram Serverless است (فایل `05`). اگر بعداً نیاز به n8n شد، می‌توان آن را دوباره اضافه کرد.
>
> **قاعده‌ی سطح اطمینان:** موارد «تأیید نشد» را قبل از استفاده بررسی کنید. دستورها و ساختار CLI ممکن است در نسخه‌های بعدی تغییر کنند؛ همیشه خروجی `npx tgcloud --help` روی سیستم خودتان را ملاک قرار دهید.

## بخش ۱ — مفاهیم پایه

| مفهوم | معنی ساده | مثال در این پروژه |
|---|---|---|
| **Bot** | حساب خودکار تلگرام که به پیام‌ها پاسخ می‌دهد | ربات Upwork Agent |
| **BotFather** | ربات رسمی تلگرام برای ساخت ربات و گرفتن توکن | ساخت ربات و دریافت توکن |
| **Update** | هر رویداد که تلگرام به ربات می‌فرستد (پیام، دکمه، …) | پیام `/check` |
| **Handler** | تابعی که برای هر نوع update اجرا می‌شود | `handlers/message.js` |
| **lib/** | کدهای مشترک بین handlerها | `gmail.js`، `llm.js` |
| **tgcloud** | ابزار خط فرمان برای deploy و اجرا | `npx tgcloud push` |
| **V8 isolate** | محیط اجرای سبک JavaScript؛ هر اجرا حافظه‌ی جدا دارد | محیط اجرای کد شما |
| **fetch** | ارسال درخواست HTTP به سرویس‌های بیرونی | صدا زدن Gmail API و LLM |
| **OAuth** | روش امن اجازه‌گرفتن از کاربر برای دسترسی به Gmail | ساخت Refresh Token |
| **Refresh Token** | توکنی که اجازه‌ی تازه‌کردن دسترسی را می‌دهد | ذخیره‌ی امن در پروژه |
| **Scope** | محدوده‌ی دسترسی | `gmail.modify` |
| **Label (برچسب) Gmail** | دسته‌بندی ایمیل؛ اینجا نقش فیلتر را دارد | `Upwork-Alerts` |
| **UNREAD** | وضعیت «نخوانده» ایمیل؛ اینجا نشانه‌ی پردازش‌نشده است | حذف UNREAD بعد از ارسال موفق |
| **MIME / HTML ایمیل** | ساختار و متن ایمیل | پاک‌سازی متن قبل از LLM |
| **Escape (HTML)** | تبدیل `<` و `>` به شکل امن | جلوگیری از خراب‌شدن پیام تلگرام |
| **LLM و fallback** | مدل زبانی و جایگزین در صورت خطا یا محدودیت | Gemini → Groq → OpenRouter |

## بخش ۲ — نصب و اولین پروژه

### ۲.۱ پیش‌نیازها
1. **Node.js 18 یا بالاتر** نصب شود (`node -v`). مستندات CLI این نسخه را لازم دانسته است.
2. یک ترمینال (PowerShell یا Terminal) باز کنید.

### ۲.۲ ساخت ربات
1. در تلگرام با **@BotFather** گفتگو کنید.
2. دستور `/newbot` را بزنید؛ نام و username بدهید.
3. **توکن** را ذخیره کنید (در جای امن، نه در Git).

### ۲.۳ ساخت پروژه
```bash
npm create @tgcloud/bot upwork-agent
cd upwork-agent
npx tgcloud login      # اتصال ربات به پروژه
npx tgcloud --help     # فهرست دستورها را ببینید
```
منبع: README بسته‌ی `@tgcloud/cli` (نسخه‌ی ۰.۲.۰، MIT).

### ۲.۴ اولین handler
یک فایل `handlers/message.js` بسازید که به `/start` جواب بدهد. ساختار دقیق را از خروجی `npx tgcloud init` یا قالب‌های نمونه (مثلاً مخزن Telegram-Serverless-Bot-Template) بگیرید. **تأیید نشد:** شکل دقیق ورودی و خروجی handler در نسخه‌ی فعلی.

### ۲.۵ تست و deploy
```bash
npx tgcloud run handlers/message    # اجرای محلی برای تست
npx tgcloud push                    # ارسال به زیرساخت تلگرام
```
منبع: مستندات (نقل‌شده در خبرها و README). `run` کد محلی را روی زیرساخت اجرا می‌کند و خروجی و `console.log` را نشان می‌دهد.

## بخش ۳ — ساخت Gmail API (گام به گام)

1. وارد **Google Cloud Console** شوید و یک پروژه بسازید.
2. **Gmail API** را فعال کنید.
3. **OAuth consent screen** را تنظیم کنید: نوع External؛ خودتان را به‌عنوان **Test user** اضافه کنید.
4. **OAuth client ID** از نوع **Desktop app** بسازید و فایل JSON را دانلود کنید.
5. یک اسکریپت محلی (روی سیستم خودتان، نه روی Telegram Serverless) بنویسید که:
   - با scope `https://www.googleapis.com/auth/gmail.modify` اجازه بگیرد،
   - **Refresh Token** را چاپ کند.
6. این توکن را در مکان امن (طبق روش tgcloud) ذخیره کنید.

> **هشدار:** این مراحل را با حساب شخصی و به نام خودتان انجام دهید. **تأیید نشد:** انقضای Refresh Token برای حساب‌های در حالت Testing، و هزینه‌ی احتمالی.

## بخش ۴ — منطق کلیدی (چرا بدون دیتابیس کار می‌کند؟)

```
/check
  → Gmail API: ایمیل‌های label:Upwork-Alerts is:unread (حداکثر ۵ تا)
  → برای هر ایمیل:
       پاک‌سازی متن → LLM (استخراج) → امتیاز با کد → LLM (پیش‌نویس اگر APPLY/MAYBE)
       → sendMessage به تلگرام
       → فقط بعد از موفقیت: حذف برچسب UNREAD
```

**ایده:** وضعیت «پردازش‌شده» را خود Gmail نگه می‌دارد. اگر ایمیلی UNREAD نباشد، دوباره پردازش نمی‌شود. این کار نیاز به دیتابیس را حذف می‌کند.

**نکته‌ی ایمنی:** ترتیب «اول ارسال، بعد علامت‌زدن» مهم است. اگر برعکس باشد، ممکن است ایمیلی علامت بخورد و هرگز ارسال نشود.

## بخش ۵ — جدول ابزارها و LLMها

### ۵.۱ زیرساخت

| ابزار | نقش | یادگیری | هزینه | یادداشت |
|---|---|---|---|---|
| **Telegram Serverless (tgcloud)** | اجرای کد و ربات | بخش ۲ | $۰ (تأیید نشد: قیمت رسمی) | JavaScript؛ بدون npm در runtime؛ بدون فایل سیستم |
| **BotFather** | ساخت ربات و توکن | بخش ۲.۲ | رایگان | توکن را امن نگه دارید |
| **Node.js 18+** | ابزار CLI | نصب معمولی | رایگان | — |
| **Gmail API + OAuth** | خواندن و علامت‌زدن ایمیل | بخش ۳ | رایگان (تأیید نشد: سقف) | scope محدود |
| **Git** | نسخه‌ی کد | `commit` و `push` | رایگان | `.tgcloud/` را ignore کنید |

### ۵.۲ LLMها

| ارائه‌دهنده | کاربرد | مدل نمونه | free tier (سطح اطمینان) | نکته |
|---|---|---|---|---|
| **Google Gemini API** | اصلی: استخراج و پیش‌نویس | Flash / Flash-Lite | اعداد متناقض؛ **تأیید نشد** | داده‌ی ورودی ممکن است برای بهبود محصول استفاده شود |
| **Groq** | fallback سریع | gpt-oss-20b (open-weight) | حدود ۳۰ RPM و ۱K RPD برای مدل‌های بزرگ (ثالث، متوسط) | محدودیت per organization |
| **OpenRouter** | fallback با مدل `:free` | مدل‌های `:free` | ۲۰ RPM؛ ۵۰ RPD بدون خرید (ثالث، متوسط) | مدل‌های free تغییر می‌کنند |
| **Ollama (محلی)** | ❌ در این معماری حذف شد | — | — | Telegram Serverless به سرویس محلی دسترسی ندارد |

**ترتیب پیشنهادی:** Gemini → Groq → OpenRouter `:free`. این زنجیره در `lib/llm.js` با fetch و تلاش مجدد پیاده‌سازی می‌شود.

**بودجه‌ی تقریبی (۲۰۰ جاب/روز):** بیشتر کار در free tier انجام می‌شود؛ اگر محدودیت‌ها کافی نبود، هزینه‌ی تقریبی چند دلار در ماه برای Gemini Flash-Lite است (منبع ثالث؛ قیمت رسمی قبل از خرید بررسی شود).

## بخش ۶ — محدودیت‌های Telegram Serverless که باید بدانید

| محدودیت | اثر روی ما | راه‌حل |
|---|---|---|
| فقط JavaScript | کد Python قابل استفاده نیست | همه‌ی منطق در JS |
| بدون npm در runtime | کتابخانه‌ی پارس MIME نداریم | پاک‌سازی ساده با کد خودمان |
| بدون فایل سیستم | فایل موقت نداریم | متن را در حافظه‌ی همان اجرا نگه دارید |
| پاسخ HTTP متنی و حداکثر ۳۰ مگابایت | ایمیل‌ها کوچک‌اند؛ مشکلی نیست | دسته‌های کوچک |
| زمان‌بند و trigger خودکار ندارد | پردازش دستی با `/check` | بخش ۲ فایل `05` |
| سقف زمان اجرا منتشر نشده | ممکن است اجرای طولانی قطع شود | ۵ ایمیل در هر بار |
| بدون مکانیزم خروجی داده | انتقال بعدی سخت است | کد را در Git نگه دارید |

## بخش ۷ — نقشه‌ی یادگیری (پیشنهادی)

1. **روز ۱:** Node.js و BotFather؛ ساخت ربات و پاسخ به `/start`.
2. **روز ۲:** `tgcloud run` و `tgcloud push`؛ تغییر یک پیام و دیدن نتیجه.
3. **روز ۳:** Gmail API و OAuth؛ گرفتن Refresh Token و لیست کردن ۵ ایمیل.
4. **روز ۴:** فرمان `/check` با لیست ایمیل‌ها و حذف UNREAD.
5. **روز ۵:** اتصال LLM (یک provider) و نمایش JSON استخراج‌شده.
6. **هفته‌ی ۲:** امتیاز، پیش‌نویس، قالب HTML و fallback.

**معیار آمادگی:** اگر بتوانید بدون راهنما یک handler بنویسید که ایمیل را بخواند، یک پیام بفرستد و UNREAD را حذف کند، برای فاز ۱ آماده‌اید.
